## Packages and why they are split

Each package depends only on the ones before it in this chain: `config`, `core`, `pg-adapter`, `apps/server`. `apps/web` uses `core` only. `actions` imports types from `core`, and `pg-adapter` and the server throw its error classes.

| Package                                                                                                         | Holds                                                                                                                                                    | Rule                                                                                                                      |
| --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| [`packages/config`](../packages/config/src)                                                                     | The zod schema for `warden.config.yaml` ([`schema.ts`](../packages/config/src/schema.ts)) and `loadConfig` ([`load.ts`](../packages/config/src/load.ts)) | Strict objects, so a typo fails startup with a `ConfigError` carrying file, line and column.                              |
| [`packages/core`](../packages/core/src)                                                                         | Pure logic: `resolveSchema`, `resolvePolicy`, filter and sort validation, record ids, cursors, roles, audit projection, action policy                    | No I/O. It also runs in the browser, so it imports `@wardenhq/config/schema`, never the package root (which loads files). |
| [`packages/pg-adapter`](../packages/pg-adapter/src)                                                             | All SQL: `introspect`, reads, writes, the audit store, sessions, migrations, the action `tx`                                                             | Identifiers come from the `EffectiveSchema` via `sql.id`; values are bind parameters.                                     |
| [`packages/actions`](../packages/actions/src/index.ts)                                                          | Published types and error classes for action modules (`defineAction`, `ActionError`)                                                                     | Its imports are type-only; apart from the error classes it is types, so action modules need nothing at runtime.           |
| [`apps/server`](../apps/server/src)                                                                             | Fastify: boot, auth, routes                                                                                                                              | Thin: parse the request, call core to validate, call pg-adapter to run it.                                                |
| [`apps/web`](../apps/web/src)                                                                                   | React + Vite UI                                                                                                                                          | Hides controls the user can't use; never the place a rule is enforced.                                                    |
| [`packages/testing`](../packages/testing/src/index.ts), [`packages/mock-oidc`](../packages/mock-oidc/README.md) | Test helpers (`startPostgres`) and the dev-only IdP                                                                                                      | Never shipped in the image.                                                                                               |

Keeping decisions in `core` makes them unit-testable without a database and shared with the UI (which imports `entityFor`, `fieldCategory` and types from it). Keeping SQL in one package makes "every identifier is quoted, every value is bound" checkable in one place.

## Boot

[`apps/server/src/index.ts`](../apps/server/src/index.ts) calls `createWarden` in [`warden.ts`](../apps/server/src/warden.ts), which:

1. Parses the environment: `parseAuthSettings` ([`auth/settings.ts`](../apps/server/src/auth/settings.ts)), `parseMigrateFlag`, `parseBodyLimit`, `parseDatabaseSettings`, and the HTTP action settings (`parseAllowHttp`, `parseMaxSteps`). Bad values throw.
2. Loads config with `loadConfig` and `requireAccess` ([`packages/config/src/load.ts`](../packages/config/src/load.ts)). Invalid config, or none with `access`, is a `ConfigError` and startup fails.
3. Opens three pools with `createDatabase` ([`database.ts`](../packages/pg-adapter/src/database.ts)): the main one, one for exports and one for custom actions, each sized so stalled exports or actions can't starve the rest.
4. Runs `migrate`, or with `WARDEN_MIGRATE=false` refuses to start if `pendingMigrations` finds any (see [the `warden` schema](#the-warden-schema-and-migrations)). Warns if `canDisableAuditTriggers`.
5. `refreshSessionEmails`, so existing sessions follow the current `access.requireVerifiedEmail`.
6. `introspect` ([`introspect.ts`](../packages/pg-adapter/src/introspect.ts)) reads the configured schemas into a `SchemaModel` ([`schema-model.ts`](../packages/core/src/schema-model.ts)). It never reads the `warden` schema.
7. `checkAuditStore` resolves `audit` config with `resolveAuditStore` ([`audit-store.ts`](../packages/core/src/audit-store.ts)) and `auditTableAccess`. A mismatch makes the store `unavailable` (writes get a 503) rather than failing startup.
8. `resolveSchema` ([`effective-schema.ts`](../packages/core/src/effective-schema.ts)) applies config to the model and returns the `EffectiveSchema` plus warnings. `resolvePolicy` ([`policy.ts`](../packages/core/src/policy.ts)) builds the `Policy`. `resolveConfigViews` ([`config-view.ts`](../packages/core/src/config-view.ts)) checks config views (errors fail startup). `resolveActor` ([`actor.ts`](../packages/core/src/actor.ts)) checks the `actor` mapping against the model.
9. Loads the actions module from `WARDEN_ACTIONS` with `loadActions` ([`apps/server/src/actions.ts`](../apps/server/src/actions.ts)), checks it with `resolveActionPolicy` ([`core/src/actions.ts`](../packages/core/src/actions.ts)) and `prepareHttpActions` ([`http-actions.ts`](../apps/server/src/http-actions.ts)). Module problems are an `ActionsError` and fail startup; config/DB mismatches disable the action with a warning.
10. `ensureSchemaSnapshot` ([`snapshots.ts`](../packages/pg-adapter/src/snapshots.ts)) records the drift baseline on first start.
11. `buildApp` ([`app.ts`](../apps/server/src/app.ts)) registers the error handler, `/healthz`, auth, then the routes, then the static UI with SPA fallback. Every warning collected above is logged.

Config that doesn't match the database (a dropped column, a table that no longer exists) only ever warns, so a schema change can't take Warden down. Invalid config files, and invalid action modules, fail startup.

## Authentication

Code: [`apps/server/src/auth`](../apps/server/src/auth/oidc.ts) and [`routes/auth.ts`](../apps/server/src/routes/auth.ts). User-facing settings: [README › Authentication](../README.md#authentication) and [auth0.md](auth0.md).

**Login.** `GET /auth/login` calls `oidc.begin()` ([`auth/oidc.ts`](../apps/server/src/auth/oidc.ts), authorization code + PKCE) and keeps the state, nonce, verifier and `safeReturnTo` destination in a short-lived signed cookie. `GET /auth/callback` checks that cookie, calls `oidc.finish()`, and refuses the login unless `resolveRoles` finds an access rule (or `actor.required` finds no user id). It then calls `sessions.start()`.

**Sessions.** `createSessions` in [`auth/session.ts`](../apps/server/src/auth/session.ts) issues a random token in a signed, `HttpOnly`, `SameSite=Lax` cookie (`__Host-` on https) and stores only its SHA-256 hash in `warden.sessions` ([`pg-adapter/src/sessions.ts`](../packages/pg-adapter/src/sessions.ts)). `touchSession` enforces the idle and absolute timeouts on every load. Starting a session revokes the browser's previous one. `POST /auth/logout` deletes it and returns the IdP's end-session URL when there is one.

**IdP tokens.** The ID token (for logout) and, with `OIDC_AUDIENCE`, the API access and refresh tokens are stored `seal`ed with AES-GCM under a key derived from the session cookie, so the sessions table alone reveals none of them. `sessions.accessTokenFor` returns a fresh access token, refreshing it once per session when it has under a minute left, or throws `SignInAgainError` (401). HTTP actions in `user` mode use it.

**Per-request guard.** The `onRequest` hook in `registerAuth` runs on every request. For `/api/*` (checked on both the raw URL and the matched route, see `isApi`) it loads the session and re-resolves roles from the stored claims, so config changes and removed assignments apply to existing sessions. No session, no roles, or (with `actor.required`) no trusted user id is a 401. It then sets `req.session` and `req.roles`. For every request it applies `csrfRejection`.

**Role resolution.** `resolveRoles` ([`core/src/roles.ts`](../packages/core/src/roles.ts)) unions roles from `access.groups` (the groups claim), `access.emailDomains` (verified email only, unless `requireVerifiedEmail` is off), and in-app assignments from `assignedRoles` ([`role-assignments.ts`](../packages/pg-adapter/src/role-assignments.ts)), matched by `assignmentEmail` and limited to roles config still defines. No match and no `allowAll` means no access. Without `access` nobody gets in. `adminAreas` ([`core/src/admin.ts`](../packages/core/src/admin.ts)) says which admin pages a set of roles opens.

**Actor user id.** With config `actor`, `resolveActor` validates the mapping at boot. At sign-in, `lookupActorUserId` ([`pg-adapter/src/actor.ts`](../packages/pg-adapter/src/actor.ts)) finds the user's id by `actorEmail` (always a verified email). The session stores the id with `actorMappingKey`, and the guard only trusts it while the mapping is unchanged. The id goes into audit entries (`actor_user_id`), soft-delete `by` columns, the `warden.actor_id` setting (`setActorSettings`), and an action's `actor.userId`.

## Read path

`GET /api/entities/:entity` in [`routes/entities.ts`](../apps/server/src/routes/entities.ts):

1. **Session**: the auth guard above.
2. **Policy**: the `preValidation` hook in `registerPolicy` ([`routes/policy.ts`](../apps/server/src/routes/policy.ts)) runs before body or query validation for every route under `/api/entities/`. An entity not in the caller's view is a 404; an action `isAllowed` denies is a 403. Methods map to actions (`GET` → read, `POST` → create, and so on); unknown methods are denied.
3. **The caller's view**: `createViews` ([`views.ts`](../apps/server/src/views.ts)) caches `schemaFor(schema, policy, roles)` per role set. It removes entities the roles can do nothing with and fields `readableBy` excludes, and makes fields `writableBy` excludes read-only. Handlers only ever use this view.
4. **Validate in core**: `validateFilter` ([`filter.ts`](../packages/core/src/filter.ts)), `searchFilter`, `resolveSort` ([`sort.ts`](../packages/core/src/sort.ts)), and `decodeCursor` ([`cursor.ts`](../packages/core/src/cursor.ts), bound to the sort and type-checked per field). Single rows use `decodeRecordId` ([`record-id.ts`](../packages/core/src/record-id.ts)); a malformed id is a 404 like a missing row.
5. **Query**: `listRows` / `getRow` ([`pg-adapter/src/rows.ts`](../packages/pg-adapter/src/rows.ts)) select only the view's fields, compile the filter with `compileFilter` ([`pg-adapter/src/filter.ts`](../packages/pg-adapter/src/filter.ts)), add `deletedCondition` for soft-deleting entities, and use `only` (via `entityTable`) so inheritance children stay out.
6. **Respond**: `toItem` attaches the `encodeRecordId` id and the `rowVersion` an update must quote; the next page gets `encodeCursor`.

A record's history (`/api/entities/:entity/:id/history`) and the audit search (`/api/audit`, `admin: [audit]`) live in [`routes/audit.ts`](../apps/server/src/routes/audit.ts). `listAuditEntries` ([`pg-adapter/src/audit.ts`](../packages/pg-adapter/src/audit.ts)) passes each entry through `projectAuditEntry` ([`core/src/audit.ts`](../packages/core/src/audit.ts)), so it only shows fields the caller can read today. `/api/capabilities` ([`routes/capabilities.ts`](../apps/server/src/routes/capabilities.ts)) tells the UI what to show; it is advisory.

## Write and audit path

`POST`, `PATCH` and `DELETE` on `/api/entities/:entity[/:id]`, and `POST …/:id/restore`, in [`routes/entities.ts`](../apps/server/src/routes/entities.ts):

1. **Session and CSRF**: the auth guard refuses unsafe methods whose `Sec-Fetch-Site` isn't `same-origin` (403) and `/api/*` POSTs without a JSON body (415).
2. **Policy**: `registerPolicy` as for reads. Writes are denied unless a role grants them; a table `deny` beats every grant. Restore needs `update` (`RESTORE_ROUTE`).
3. **Reason**: `reasonFor` calls `checkReason` ([`core/src/reason.ts`](../packages/core/src/reason.ts)) against the entity's `requireReason` and `reasonMinLength`, which `resolveSchema` set from `defaults.requireReason` or the table's own.
4. **Values**: `validateRecord` ([`core/src/validation.ts`](../packages/core/src/validation.ts)) against the caller's view. It is a strict object, so unknown, hidden and unreadable fields are rejected like nonexistent ones, and read-only ones are refused.
5. **Transaction**: `createRow`, `updateRow`, `deleteRow`, `softDeleteRow` or `restoreRow` ([`pg-adapter/src/writes.ts`](../packages/pg-adapter/src/writes.ts)) open a transaction, `setActorSettings` (for your triggers), and for an existing row lock it (`lockRow`) and compare its `rowVersion` with the version the client read (409 on mismatch). Then they write and return only exposed fields. The `*In` variants (`insertIn`, `updateIn`, …) do the same inside an existing transaction for custom actions.
6. **Audit**: each write calls its `onWrite` hook, `auditHook` ([`pg-adapter/src/audit.ts`](../packages/pg-adapter/src/audit.ts)), inside the same transaction. It records actor, roles, request id, reason, before/after/diff and the written fields with `insertAuditEntry`. If the insert fails the write rolls back (`AuditWriteError`, a 500), so the log holds every write or none.
7. **Errors**: `mapWriteError` ([`pg-adapter/src/errors.ts`](../packages/pg-adapter/src/errors.ts)) turns constraint violations into 400/409 with field details, naming only exposed fields. `isDataError` becomes a generic 400. Anything else goes to the error handler in `buildApp`, which logs it and answers a generic 500.

**Audit store.** `resolveAuditStore` ([`core/src/audit-store.ts`](../packages/core/src/audit-store.ts)) turns config `audit` into `{ kind: 'warden' }` (`warden.audit_log`), `{ kind: 'table', … }` (your table and column mapping) or `{ kind: 'unavailable' }`, whose writes and reads throw `AuditUnavailableError` (503). `resolveSchema` never exposes the audit table, whatever else config says. `warden.audit_log` is append-only through triggers (migration `0002_audit_log` in [`migrate.ts`](../packages/pg-adapter/src/migrate.ts)). See [database.md › The audit log](database.md#the-audit-log) and [Writing the audit log to your own table](database.md#writing-the-audit-log-to-your-own-table).

**Soft delete.** With `tables.<t>.softDelete`, `resolveSchema` sets `entity.softDelete` (via `resolveSoftDelete`). `DELETE` then calls `softDeleteRow` (setting the column and `by`), restore calls `restoreRow`, lists take `deleted=exclude|include|only`, and the audit entry carries `SoftDeleteDetails`. See [config.md › Soft delete](config.md#soft-delete).

**Hard delete.** `resolvePolicy` puts `delete` in `policy.denied` for every entity without `allowDelete` (or `defaults.delete: granted`) that doesn't soft-delete, and records those in `policy.deleteOff`. `resolveActionPolicy` disables any action whose permissions would delete there. `deleteCascadeWarnings` warns about tables a role or action may hard-delete from whose foreign keys change other rows (hidden tables included), since those changes bypass policy and the audit log. See [config.md › Hard delete](config.md#hard-delete).

## Custom actions

User docs: [actions.md](actions.md). Design: [RFC 0001](rfcs/0001-define-action.md).

**Loading.** `loadActions` ([`apps/server/src/actions.ts`](../apps/server/src/actions.ts)) imports the `WARDEN_ACTIONS` module once, passing it `actionsApi` (Warden's own zod, `defineAction`, `ref`). `checkActionDefinitions` ([`core/src/actions.ts`](../packages/core/src/actions.ts)) validates the definitions into `ActionSpec`s. `resolveActionPolicy` matches them to the schema, policy and config `actions` grants.

**Routes** ([`routes/actions.ts`](../apps/server/src/routes/actions.ts), `registerActionRoutes`): `GET /api/actions`, `GET /api/actions/:name/defaults`, and `POST /api/actions/:name/preview`, `/run` and `/retry`. The list shows `runnableActions`; every per-action route starts with `authorize`, which calls `canRunAction`: an action the caller can't run is a 404, like a nonexistent one. A granted action is a deliberate escalation, so the caller needs read on its entity but not the table grants for what it writes.

**Transactional (`run`) actions.** `execute` validates records and input, takes a slot (`createSlots`, [`slots.ts`](../apps/server/src/slots.ts)), and opens a transaction on the action pool (`startDetachedTransaction`). Inside it: `setActorSettings`, lock the target rows in key order (`lockKeyedRows`), load `ref` inputs (`resolveRefs`), write the parent audit entry with `insertActionEntry`, and call `run` with the `tx` from `createActionTx` ([`pg-adapter/src/action-tx.ts`](../packages/pg-adapter/src/action-tx.ts)). `tx` reuses the CRUD validators and `insertIn`/`updateIn`/`deleteIn`, refuses writes outside the action's `permissions` or past `maxAffectedRows`, and audits each row with `auditHook` under the parent's `parentId`. A preview runs the same work and rolls back, returning the changes the caller may see and a `previewToken` (an HMAC of `previewTokenPayload` under the session secret). A run that quotes the token and would change something different gets a 409 `preview_stale`. Past the deadline the connection is destroyed (rolled back) and the caller gets a 503. `afterCommit` callbacks run after commit.

**HTTP actions** ([`http-actions.ts`](../apps/server/src/http-actions.ts)). An action with `http` can't be previewed. The same transaction locks the records and commits the attempt's audit entry before any request is sent. Then `runHttpAction` calls the endpoint (`perRecord` fans out with bounded concurrency) with an idempotency key and the `X-Warden-Context` header, signed by `signRequest` in the HMAC modes. Credentials come from `credentialsFor`, per `http.auth`: an HMAC secret (`hmac`), a cached M2M token plus the HMAC signature (`client_credentials`), or the user's own access token via `accessTokenFor` (`user`). The log is append-only, so the API's answer is a second entry whose `details.outcome` points at the attempt.

**Multi-step HTTP actions.** With `http.steps`, `runHttpSteps` calls each step in order, feeding earlier responses to later `url`/`body` functions. It stops at the first failure and runs `compensate` for completed steps in reverse. `POST /api/actions/:name/retry` resumes a failed attempt from its first unfinished step. It holds the attempt with `withActionAttempt` (an advisory lock), reloads it with `loadActionAttempt`, and refuses after `RETRY_WINDOW_MS` or when the input or records changed. Steps' results are recorded in the attempt's outcome entries, and `stepsProgress` ([`core/src/http-action.ts`](../packages/core/src/http-action.ts)) reads them back to find where to resume.

## Exports

`GET /api/export/:entity` in [`routes/export.ts`](../apps/server/src/routes/export.ts) sits outside `/api/entities/`, so it does the policy hook's checks itself: 404 outside the caller's view, 403 without `export` (which also needs `read`). It validates the grid state with `validateViewState` ([`core/src/saved-view.ts`](../packages/core/src/saved-view.ts)), takes an export slot, and calls `openExport` ([`pg-adapter/src/rows.ts`](../packages/pg-adapter/src/rows.ts)), a read-only repeatable-read transaction with a cursor on the export pool. Exports over `MAX_EXPORT_ROWS` are refused. `recordExport` commits the audit entry before the first row is sent, then rows stream through `csvRow` ([`core/src/csv.ts`](../packages/core/src/csv.ts)). Idle and deadline timeouts destroy the response so a cut-off download never looks complete.

## Saved and config views

Users' saved views live in `warden.saved_views` ([`pg-adapter/src/saved-views.ts`](../packages/pg-adapter/src/saved-views.ts)) and are served by `registerSavedViewRoutes` ([`routes/saved-views.ts`](../apps/server/src/routes/saved-views.ts)). Each is checked with `validateViewState` against the entity as the viewing user sees it, so a view never reveals a field. Sharing takes `admin: [views]`. Views from config (`tables.<t>.views`) are resolved at boot by `resolveConfigViews` and listed alongside, with ids from `configViewId`; `defaults.sharedViews` (`config`, `ui` or `both`) decides where shared views come from. "Export to config" builds YAML with `toExportedView` and `viewsConfigYaml`. See [config.md › `tables.<table>.views`](config.md#tablestableviews).

## Admin pages

Each is gated by an `admin` area on a role (`adminAreas`) and is a 404 to everyone else:

- **Schema drift** (`schema`): [`routes/schema-drift.ts`](../apps/server/src/routes/schema-drift.ts) diffs the live model against the stored snapshot with `diffSchema` ([`core/src/schema-drift.ts`](../packages/core/src/schema-drift.ts)); acknowledging calls `acknowledgeSchemaSnapshot`.
- **Roles** (`roles`): [`routes/roles.ts`](../apps/server/src/routes/roles.ts) assigns and unassigns roles (`assignRole`, `unassignRole`; `lastHolderRoles` keeps the last `admin: [roles]` assignment when no `access` rule grants that role) and revokes a user's sessions (`deleteSessionsForSubject`). Each change is written to the audit store.
- **Audit log** (`audit`): the `/api/audit` search above.
- **Views** (`views`): sharing saved views.

## The `warden` schema and migrations

Warden's own tables live in the `warden` schema (`WARDEN_SCHEMA` in [`introspect.ts`](../packages/pg-adapter/src/introspect.ts)), which `introspect` skips, so it is never exposed:

| Table                      | Written by                                                                                                |
| -------------------------- | --------------------------------------------------------------------------------------------------------- |
| `warden.schema_migrations` | `migrate`                                                                                                 |
| `warden.sessions`          | [`sessions.ts`](../packages/pg-adapter/src/sessions.ts) (hashed tokens, sealed IdP tokens)                |
| `warden.audit_log`         | [`audit.ts`](../packages/pg-adapter/src/audit.ts) (append-only; unused when `audit` points at your table) |
| `warden.schema_snapshots`  | [`snapshots.ts`](../packages/pg-adapter/src/snapshots.ts)                                                 |
| `warden.role_assignments`  | [`role-assignments.ts`](../packages/pg-adapter/src/role-assignments.ts)                                   |
| `warden.saved_views`       | [`saved-views.ts`](../packages/pg-adapter/src/saved-views.ts)                                             |

Migrations are the `MIGRATIONS` list in [`migrate.ts`](../packages/pg-adapter/src/migrate.ts). `migrate` applies pending ones in one transaction under an advisory lock, so replicas starting together don't race, and records each version in `warden.schema_migrations`. To change the schema, append a migration with the next version number: an applied migration never runs again, so editing one changes nothing on existing databases. Deployments that run Warden as a restricted role set `WARDEN_MIGRATE=false` and run [`apps/server/src/migrate.ts`](../apps/server/src/migrate.ts) (`node dist/migrate.js`) as the owner. See [database.md](database.md).

## The web UI

[`apps/web`](../apps/web/src) is a React + Vite app served by the server from its build directory. Routes are in [`routes.tsx`](../apps/web/src/routes.tsx), pages in [`pages`](../apps/web/src/pages/entity-page.tsx), and API calls go through `apiFetch` in [`lib/api.ts`](../apps/web/src/lib/api.ts) (same-origin, JSON). It reads `/api/schema` (the caller's view) and `/api/capabilities` to decide what to show. The Help page ([`help-page.tsx`](../apps/web/src/pages/help-page.tsx)) mirrors [using-warden.md](using-warden.md); change both together. E2E tests in [`e2e/tests`](../e2e/tests/viewer.spec.ts) drive the compose stack through the mock IdP.

## Security invariants

The rules in [CLAUDE.md](../CLAUDE.md#core-rules-security-relevant-dont-break-these), and where each is enforced. A change near any of these needs tests for the deny and failure paths.

| Invariant                                                                                                                                                 | Enforced in                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Config narrows defaults.** Reads allowed unless hidden; writes denied unless granted; a table `deny` beats every grant; hard delete off unless enabled. | `resolvePolicy` and `isAllowed` in [`core/src/policy.ts`](../packages/core/src/policy.ts); `resolveActionPolicy` and `canRunAction` in [`core/src/actions.ts`](../packages/core/src/actions.ts) for actions.                                                                                                                                                                                                                                            |
| **Hidden means absent.** Hidden tables and columns never selected, returned or accepted; same 400/404 as nonexistent.                                     | `resolveSchema` in [`effective-schema.ts`](../packages/core/src/effective-schema.ts) removes them; `schemaFor` in [`policy.ts`](../packages/core/src/policy.ts) does the same per role for `readableBy`; `registerPolicy` 404s entities outside the view; `validateRecord`'s strict object rejects unknown fields; `rows.ts` and `writes.ts` select only `entity.fields`; `mapWriteError` names only exposed fields; `projectAuditEntry` trims history. |
| **Only the `EffectiveSchema` decides what exists.** Identifiers from it, quoted with `sql.id`; values bound.                                              | Every query in [`packages/pg-adapter/src`](../packages/pg-adapter/src/rows.ts); `compileFilter` in [`filter.ts`](../packages/pg-adapter/src/filter.ts). The only `sql.raw` calls take fixed keywords (`asc`/`desc`, `<`/`>`, column types) or Warden's own migration SQL.                                                                                                                                                                               |
| **Validate client input in core** (filters, sorts, ids, cursors) before pg-adapter.                                                                       | `validateFilter`, `resolveSort`, `decodeRecordId`, `decodeCursor`, `validateRecord`, `validateViewState` in [`packages/core/src`](../packages/core/src/filter.ts), called from the route handlers.                                                                                                                                                                                                                                                      |
| **Config/DB mismatches warn; invalid config fails startup.**                                                                                              | Warnings from `resolveSchema`, `resolvePolicy`, `resolveActionPolicy`, `resolveActor`, `resolveConfigViews` and `checkAuditStore`, logged in `createWarden` ([`warden.ts`](../apps/server/src/warden.ts)); `ConfigError` from [`load.ts`](../packages/config/src/load.ts).                                                                                                                                                                              |
| **Don't leak internals.** 5xx bodies are generic; details go to the log.                                                                                  | The error handler in `buildApp` ([`app.ts`](../apps/server/src/app.ts)) and its not-found handler; `mapWriteError`; request logs pass through `redactingLogger` ([`logging.ts`](../apps/server/src/logging.ts)).                                                                                                                                                                                                                                        |
| **Permissions enforced on the server.** The UI only hides controls.                                                                                       | `registerPolicy` ([`routes/policy.ts`](../apps/server/src/routes/policy.ts)) for `/api/entities/*`; the export, action, audit, saved-view and admin routes check `isAllowed`, `canRunAction` or `adminAreas` themselves. `/api/capabilities` is advisory.                                                                                                                                                                                               |
